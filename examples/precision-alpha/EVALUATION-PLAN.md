# Evaluation plan — declared before the run

Written 2026-09-20 against `claude/eager-ramanujan-razak3` at `95ba9540`,
**before the harness existed and before any case below was run**. The point
of writing it first is that the scoring rules cannot be adjusted once the
numbers are in. If something here turns out to be a bad rule, it stays, and
the write-up says it was a bad rule.

The pack under test is the DE440s-derived pack
`4cc6f85af54c98a890c1dd1022d5c13496df7d1d06d145c1c0bbbe1b94069764`,
covering 1849-12-25 .. 2150-01-21. Both search modes are evaluated:

- **empirical-apparent** — `runtime.search({kind:'longitude'})`, apparent
  geocentric ecliptic longitude of date. Support is conditional at best.
- **validated-geometric** — `runtime.searchGeometric()`, geometric J2000
  ecliptic longitude. Support can be proven.

They compute different quantities, so each is scored against a reference
scan of **its own** function. Their event instants are not expected to
agree with each other and no cross-mode agreement is scored.

## What counts as the truth

For every case, a dense independent scan of the same function:

- step **1/512 day** (≈ 2.8 minutes), with the grid phase offset by
  φ = 0.3819660112501051 of a step so it does not land on rational roots;
- a root is a sign change of `wrap180(f(t) − target)` whose endpoint
  difference is under 180°, so an antipode wrap is not counted as a root;
- each sign change bisected to **1e-9 day** (≈ 86 µs);
- roots within 1 second of an interval endpoint are recorded as boundary
  roots and reported separately.

A denser scan is **corroboration, not a proof**. It can miss a root pair
closer together than one step, and it can miss a tangency that does not
change sign. Where the validated mode establishes completeness, the
mathematical statement is the mode's own, from true bounds on the stored
polynomial; the scan is there to catch the mode being wrong, not to make it
right. Where the scan and a proven result disagree, the disagreement is
reported as a finding and investigated, not resolved by preferring one.

## Matching, and the accuracy target

- A reference root `r` is **matched** by a returned event `e` when
  `|e.ttDays − r| ≤ 1 second` **and** `r` lies inside `e`'s reported bracket
  widened by one bracket width.
- **missed** = reference roots matched by no returned event.
- **extra** = returned events matching no reference root. Two events
  matching the same root: one is matched, the rest are extra.
- **unresolved** = the run left at least one interval undecided, or was
  refused, or finished with `support: 'none'` while the reference found
  events.

**The target, fixed now:** on every case, for both modes,
`missed = 0 and extra = 0`. Additionally, wherever
`completeness.established` is true, the returned count must equal the
reference count exactly — a proven result that is merely a subset is a
failure of the proof, not a near miss.

## Usefulness, fixed now

A solver that refuses everything is not a successful product. So, per mode:

- **unresolved fraction** = unresolved cases ÷ scored cases.
- Above **25%**, the mode is reported as a *failure of usefulness* however
  good its accuracy is.
- A mode that is refused on a case still has that case counted in its
  denominator. Refusals are not skips.

Reported per case and per mode, separately, never combined into one score:
missed, extra, unresolved, evaluations, wall-clock milliseconds, and peak
`heapUsed` delta in MiB.

## C · Structural invariants

Each is a property the result must have regardless of how many events there
are, checked on every holdout case unless stated otherwise.

| # | invariant | rule |
| --- | --- | --- |
| C1 | **partition** | splitting the window into 2, 3 and 7 equal parts and concatenating the results gives the same event set as the whole, after boundary deduplication |
| C2 | **boundary convention** | an event within 1 second of an internal partition boundary is counted once. The convention is declared here: a part owns `[from, to)`, so a root exactly at a boundary belongs to the later part |
| C3 | **±360°** | targets `t`, `t + 360` and `t − 360` give the same event set |
| C4 | **equivalent representation** | target `t` and target `t + 720` give the same event set |
| C5 | **window shift** | shifting the window later by 37 days gives, inside the overlap, the same events |
| C6 | **sampling settings** | `probeSamples` at 97, 193 and 385 (empirical) and `minWidthSec` at 1e-3, 1e-4, 1e-5 (validated) give the same event set to within the matching tolerance |
| C7 | **budget exhaustion** | `maxEvaluations: 500` finishes with `execution.status: 'budget-exhausted'`, `completeness.established: false`, and the events it did find are real |
| C8 | **cancellation** | a signal aborted partway gives `execution.status: 'cancelled'` and never an established completeness |
| C9 | **recovery** | a normal search immediately after a cancelled one returns the same result as if the cancel had never happened |
| C10 | **unsupported options** | an unknown option key, an out-of-range value, and a reversed interval are each refused with a code, not silently normalised |

C1–C6 are set comparisons under the same 1-second matching rule.

## What is not measured here

Agreement with the sky, with Swiss Ephemeris, or with any other ephemeris.
Agreement with `/birth-chart/`. Compression ratio. Anything about a body
outside the pack's ten. Anything about WebKit.
