### The one thing added after seeing a result

C7 and C8 fixed literal constants — a 500-evaluation budget and an abort at
poll 300. On the slow bodies the validated mode answers the whole case in
**18 to 173 evaluations**, so the budget is never spent and the abort never
fires. Those runs are neither passes nor failures of the invariant: the
case cannot exercise it. Recording them as passes would have been the
dishonest option, and recording them as failures would have blamed the
solver for being fast.

So the harness reports a third outcome, **not exercised**, with the cost
that made it so — and C7b/C8b were added, setting the limit to half the
case's own measured cost so every case does exercise the invariant. The
declared C7 and C8 stay exactly as written and are reported beside them.
This is a change to the *measurement*, not to the target or the scoring
rules, and it is written here rather than folded in quietly.

## What changed in the implementation because of this evaluation

**Cancellation is now a result, not an exception.** The v2 contract names
four execution states and `cancelled` is one of them; before this run,
nothing could produce it — both modes threw. A state the contract
advertises that cannot occur is a lie about the contract, and a throw
discards every root the validated mode had already proved. Both modes now
return a result with `execution.status: 'cancelled'`, `finished: false`,
`established: false`, and, in the validated mode, the events isolated so
far. Two tier-A tests that pinned the old throw were rewritten to pin the
new behaviour.

One limitation stays, stated rather than fixed: on the **empirical** mode a
cancelled or budget-exhausted run returns **zero** events even when
segments had already been decided, because that path reports through the
empty-result shape. The events are not wrong, there are just none. Carrying
partial segment verdicts out of that path is worth doing and is not done
here.
