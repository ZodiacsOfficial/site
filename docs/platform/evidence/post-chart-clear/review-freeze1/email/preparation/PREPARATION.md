# Independent baseline preparation — no frozen-source acceptance

The current observed root was c3001114d4058ecb17e0274774ac465aa9f59dad. Both EmailCaptureEnhancement.astro and EmailCapture.astro were captured with read-only git show; a second exact git-show comparison proves they are byte-identical at the author's c7b9eb4a769e39a46aebc0a5ecedcb9fc40949e3 base. No moving author source was read during preparation.

The independently written native fixture executes the complete actual enhancement script, transpiled without substitutions, against native DOM shells matching the source's consumed form/control/data attributes. The representative shells cover a chart-triggered daily form, a weekly footer and a standalone daily horoscope form. Form events, validity, FormData serialization, radio defaults, reset, microtasks, visibility and focus are native Chrome. Fetch is a deferred in-memory transport, and requestAnimationFrame delivery is controlled to expose ordering. No real subscriber, backend request or rollout is involved; this is not a full Astro page or lifecycle-island integration check.

The final baseline run has 20 independent groups: 10 pass and 10 fail, with zero page errors or network requests. The 10 failures expose missing hide-on-clear, old success/failure/finally after clear, old success resetting replacement values/sign, old completions ending a newer pending submit, old focus after clear or a reopened replacement chooser, old reset microtask collapsing a new chooser and replacement-computed-only stale success. Current success/reset, failure/retry, validation, positions-only non-reveal and standalone forms remain passing controls.

Initial 18-group and 19-group runs are retained. A nineteenth group was added because the simpler replacement-focus control passed baseline merely when its target was hidden: reopening the replacement chooser and flushing only the old frame produces the actual stale focus, while the later new frame remains a positive control. Root then requested an explicit same-chart form-edit boundary check: the twentieth group confirms the unchanged current completion can reset later typed email/sign edits when no chart clear/replacement occurred. This is an existing limitation, not a promise of cancellation on every edit. The final same driver will be used unchanged against the frozen correction unless a separately recorded fixture defect requires repair.

Already submitted subscription requests remain distinct from downstream presentation. Successful responses are expected to retain once-only existing subscription analytics even if chart-owned UI has become obsolete.
