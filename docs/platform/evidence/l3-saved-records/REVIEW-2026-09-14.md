# Adversarial review of the L3b/c candidate (2026-09-14)

Four independent reviewer sessions attacked the working tree from fixed lenses
(native IndexedDB protocol, authority and fencing, product honesty, acceptance
coverage), each free to run probes against the bundled production modules in
Chromium; a second stage tried to refute every major finding against the tree as
it stood after fixes. Findings that named the committed revision only were
confirmed as fixed in the working tree by the refutation stage. Everything below
is now in the candidate; the "not changed" rows record deliberate decisions.

| Lens | Finding | Disposition |
| --- | --- | --- |
| native | Owner erasure intent pinned to the owner generation only: after a device erasure the same owner is readmitted at generation 1, so a device-era handle or pre-wipe ticket could purge the readmitted namespace (reproduced natively) | Fixed: `requestErasure(target, expected, expectedDevice)` refuses an owner intent whose device generation rotated; handles pass the device generation they observed and tickets carry it. Unit, fake and native groups added (device cycle fence; device readmission racing a pre-wipe ticket). |
| native | `abort()` overwrote the first failure cause with the AbortError Chromium fires on cancelled requests | Fixed (`??=`); native group "adapter revocation while a write is queued" pins `stale`, no commit, rows unchanged. |
| native | `mayHaveCommitted: true` for a readwrite that queued no write (clear of an already-erased owner) | Fixed: only a queued write can report ambiguity; `clearOwner` reports a committed intent, not the empty transaction. Unit case added. |
| native | `IDBDatabase.onclose` unhandled, leaving a dead connection for the handle's lifetime | Fixed: forced close aborts pending work like `versionchange`; unit case added. |
| native | "Remove all records on this device" ran an owner-namespace erasure | Fixed: copy names the listed records in every locale; device-wide removal stays with "Sign out · clear all Zodiacs data". |
| authority | Account panel blocked every signed-in path (bound, mismatch, unowned-with-legacy) when record discovery failed, with a false "sign-in stays locked" message | Fixed: only an empty-looking browser is gated (the bootstrap's own rule); the message no longer claims the tab is locked. Source-inspection test added. |
| authority | Guest-view selection survived re-authentication and re-applied itself on the next retained sign-out | Fixed: an account grant consumes the per-tab selection. Unit case retained→guest→account→retained. |
| authority | Read-only rights were advisory: a retained scope's store still accepted `create` | Fixed at the store: read-only authority refuses `create` with `access-denied`. Unit case added. |
| authority | A removal in another tab was invisible to an open calculator; "Keep again" could never succeed until reload | Fixed: record-scope changes are broadcast through a localStorage key other tabs listen to, an admitting keep broadcasts too, and a refused keep re-opens the scope. Lifecycle checks "removal in another tab" and "two tabs keeping at once" added. |
| authority | Destructive legacy actions are refused when record storage is unavailable | Not changed: fail-closed is deliberate, so "clear all" never claims a device is clean while records it cannot reach remain. The message names the state. |
| authority | A device ticket prepared before a later owner admission still purges that owner | Not changed: a whole-device clear is what the visitor asked for; the other tab's lease is revoked before the lock is granted. Recorded as a limit of the ticket, not an invariant. |
| coverage | Confirmed-deletion erasure was authorized by an epoch sampled after the asynchronous plan | Fixed: the epoch is captured before the plan and re-checked after it. |
| coverage | Browsers without `indexedDB.databases()` could never bind an account on a fresh browser | Changed: unsupported storage (no discovery API, unreadable schema) cannot hold records this client kept, so it never blocks binding; pending or failed discovery still does. Bootstrap test updated. |
| coverage | "Blocked upgrade" native group accepted both outcomes | Not changed; the README now states the behaviour the group proves (the live connection closes, the next operation reopens or fails closed). |
| honesty | Empty, erased and full states were worded device-wide while another namespace held records; an account was never told hidden guest records exist | Fixed: copy is scoped to the listed records in every locale; signed in, the panel names the hidden guest records and how they are removed. Lifecycle assertion added. |
| honesty | A missing `indexedDB.databases()` was described as "a version this site cannot read" | Fixed: the unsupported state names both causes. Lifecycle check with the API deleted added. |
| honesty | "Locked" promised a check that would finish; the calculator asserted a guest scope while the mode was unknown | Fixed: locked copy tells the visitor what resolves it; the scope line renders only once the mode is known. |
| honesty | Losing a cross-tab admission race turned an explicit keep into a silent no-op | Fixed: a "changed" outcome states that nothing was stored and offers an explicit second keep; the outcome survives the re-open. |
| honesty | Record labels were copied from a matched legacy chart name | Fixed: labels come from the calculation itself. |
| honesty | "Kept on this device." rendered twice | Fixed: short button label, one status line with the Profile link. |

Coverage gaps the reviewers listed at the time: hydrated interaction tests
for the records panel (its states are covered by the browser drives only), an
unknown-time keep and a 40-record "full" state in the browser drive, sign-out
"clear all" and account deletion through the real account panel in a browser,
and any browser other than Chromium. The 2026-09-15 hardening pass closed all
but the first (unknown-time keep and the 40-record refusal in the lifecycle
drive; the real bootstrap and account panel driven with intercepted auth and
backend responses; Firefox runs of the native drive and representative
lifecycle checks) and revised the "device ticket" row above: an observed
absence is now re-checked under the exclusive transition. See
[HARDENING-2026-09-15](HARDENING-2026-09-15.md).
