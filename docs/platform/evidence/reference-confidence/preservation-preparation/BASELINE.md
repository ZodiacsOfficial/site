# Executed baseline controls before C-015 freeze

The f803 baseline was exercised in actual Chrome 152 with Node 22.23.2, actual Preact/Chart and rc.6 calculation/receipt code. The identity records 211 real source/dependency inputs and three declared transformations: Chart import gates plus pass-through resolver and endpoint counters. No moving candidate was tested.

Fifteen controls passed in the first execution. The two actual-local-save controls stopped before persistence because the reviewer's `.invalid` HTTP fixture origin was not a secure context and native `crypto.randomUUID` was undefined. A separate two-origin browser probe confirms the precise difference: insecure `.invalid` has no randomUUID, while the otherwise identical loopback origin is secure and supplies the native function. The driver changed only to loopback and added an affected-case filter; both local-save controls then passed. The original driver, full result and failure logs remain unmodified. Thus there are seventeen accepted baseline controls drawn from two executions, with two original reviewer-fixture failures retained. No product/auth defect or permission bypass is inferred.

The ordinary unknown-time New York case currently makes one endpoint helper call and two direct `computeBodies` endpoint calls, then exposes a Pisces Moon and Gemini Registry bridge. That is a concrete observation of prior behavior, not evidence that this particular Sun or Moon is false. C-015 is expected to withdraw unproven confidence while preserving its computed reference and receipt. The independent child supplies the distinct historical Moon counterexamples.

The ten primary controls cover New York known/unknown time, Bangkok leap day, Paris seconds offsets, Manaus, a long Apia reference, unknown/known exact pole, signed-offset fallback and Chart moon mode. The baseline captures pre-augmentation chart JSON, the committed numerical fields, optional immutable envelope JSON, direct call sequence and Registry context. Known-pole and signed-offset controls legitimately use the existing legacy calculation without a receipt. The native Blob download exactly matches the captured immutable Paris receipt bytes. Replacement during a delayed receipt-module load computes only the latest input. Editing a known result clears its Registry bridge before an unknown replacement. The existing skipped-date safeguard rejects before primary/receipt/endpoint work, and public positions imports call none of those operations.

Each corrected local-save control executes the actual legacy store exactly once in a disposable context. Birth input, saved summary and emitted reference-Sun context are retained for frozen-candidate comparison. IDs and timestamps are naturally generated; equality will compare the stable birth/summary fields, not those incidental values. This preserves a local write contract and does not certify real account authority, backend synchronization, whole-date Sun confidence or reversible cancellation of already requested writes.

Candidate acceptance remains pending the author's immutable freeze. All files here belong to the review scratch; no root, author, source repository, SDK, remote service or shared platform document was modified.
