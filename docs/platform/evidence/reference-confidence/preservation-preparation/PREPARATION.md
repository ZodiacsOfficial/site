The approved narrow policy is sound as a conservative removal of an unsupported confidence inference. The existing `moonCandidates` contract already interprets an explicit empty array as unverified, and `moonIsUncertain` then keeps a lone reference longitude from becoming a settled Moon label. Reusing that contract avoids inventing another public confidence schema or silently making endpoint sampling authoritative again. The `moonAmbiguousNotice` wording must describe missing verification rather than claim an observed sign change; consumer text/reading/share consequences are the child's independent scope.

For unknown time, the primary calculation currently succeeds before Chart calls the date-endpoint helper and two body-position evaluations. It then assigns endpoint Moon candidates and may choose a singular Sun Registry record if the sampled signs agree. Removing those confidence operations should leave primary reference resolution, witness validation, calculation and envelope serialization unchanged. It also avoids rejecting a successfully computed point because a later confidence lookup fails, but no injected failure is an observed IANA/ephemeris defect by itself. Our counters distinguish these two direct endpoint body calls from the actual primary ephemeris work; “zero numerical work” would be false.

The portable helper serializes the envelope before the caller augments presentation metadata. Its returned string is immutable. The review will compare that string byte-for-byte, pre-augmentation chart bytes, and the committed chart's numerical fields after omitting only `moonSignCandidates`. This catches accidental mutation of coordinates, flags, instant, houses, aspects, bodies or provenance. It also covers signed-offset and exact-known-pole legacy paths which legitimately have no portable envelope. The existing optional-module failure and no-recalculation-on-portable-failure rule remain outside this change and must not be weakened.

The singular Sun Registry bridge is a separate actionable claim. Disabling it for every unknown-time input sacrifices some valid links, but preserves the existing known-time path without claiming an observed false Sun. The exact bridge DOM and its impression/click gating must be tested; the sanctioned records cross-link and optional saved-chart Registry Collection path are different code paths. The latter must remain unchanged. Reference-Sun naming, `chart-computed`, post-chart daily context and legacy saved-summary bodies remain as existing, explicitly open product limitations. A hidden Registry link does not settle those broader semantics or stop an already requested save.

Two defensible options were compared:

1. Apply the approved explicit unverified sentinel and remove endpoint confidence calls. It works in existing runtimes, preserves the useful point calculation and receipt, and fails the singular Registry gate conservatively. This is the smallest bounded slice.
2. Introduce a validated whole-date coverage plus body-extrema/crossing proof before exposing candidates or Registry. Native Temporal availability alone supplies neither all-runtime date coverage nor astronomical candidate completeness; the inactive interval provider cannot by itself justify this. That is a separate algorithm and compatibility policy, not a safer small substitute here.
