# Preregistration — frozen before any candidate is tuned

Written 2026-09-20, before a single coefficient was fitted. Everything in the
"already known" section below was derived by reading the *committed* reports of
the previous study; nothing here was learned by tuning a new candidate, and
nothing below has been adjusted after seeing a result. If a target is missed,
this file is what the miss is measured against.

## What was already known when these targets were set

Two things, both from re-analysing committed evidence rather than from new
experiments.

**The previous comparison had the confound its own report names.** The
prototype's best figure was taken with Delta-T pinned to the reference's value;
the shipped core was never re-run that way. `CONTROLLED-BASELINE.md` in this
directory now fills the missing cell. The corrected attribution is that with
the clock held fixed, the series change takes worst-case longitude agreement
from **17.40″ to 0.134″** — not from 64.8″, which mixed the clock in.

**The prototype's remaining 0.134″ is almost entirely not the ephemeris.** The
per-case residual is common-mode: at a given instant all ten bodies move
together, and two cases at the same instant give identical offsets. Regressing
that common-mode term against the two libraries' nutation-in-longitude
difference gives **r = 0.99992, slope 1.0005**, leaving a constant −0.0075″.
So the DE positions already agree with Swiss far better than 0.134″, and the
ceiling is astronomy-engine's truncated nutation series, which the prototype
reuses by design.

That changes what the compression budget is competing against, which is why it
is recorded here rather than discovered later.

## Effective coverage, stated exactly

`de440s.bsp` sha256 `c1c7feeab882263fc493a9d5a5b2ddd71b54826cdf65d8d17a76126b260a49f2`,
32,726,016 bytes, 14 segments, all type 2, every one covering

```
1849-12-26T00:00:00 TDB .. 2150-01-22T00:00:00 TDB
```

Not "1850–2150". Segment ids present: barycentres 1–9 and the Sun (10) relative
to the solar-system barycentre; 301 (Moon) and 399 (Earth) relative to the
Earth–Moon barycentre; 199 (Mercury) and 299 (Venus) relative to their own
barycentres. **There are no body-centre segments for Mars through Pluto** —
only barycentres — which is a fact about the output contract, not a choice, and
is recorded in `OUTPUT-CONTRACT.md`.

Usable coverage is narrower than segment coverage, because light-time lookback
reads the target earlier than the epoch (up to ~6 hours for Pluto) and the
central-difference velocity reads ±60 s either side. Any equal-coverage claim
below means the segment interval above, minus that margin, for every dependent
segment.

## Targets

Engineering targets, chosen before measurement. Not guarantees, not
measurements, and not a rating.

| # | target | measured how |
| --- | --- | --- |
| T1 | **≥ 4× smaller** than 31.21 MiB over *matched* effective coverage and body set — so ≤ **7.80 MiB** | compiled pack bytes on disk, uncompressed and gzipped, both reported |
| T2 | **≤ 0.05″** additional maximum longitude disagreement introduced by the representation, against the **uncompressed prototype** | same instants, same reduction, same time policy; the only change is the coefficient source |
| T3 | **≤ 0.5″** maximum longitude disagreement with the configured Swiss reference under matched conventions, on the expanded set | `compare.mjs`, SWIEPH verified per call |
| T4 | warm latency **better than** the prototype's 0.324 ms p50 for 10 bodies, with **no regression** in warm p95, cold start, peak RSS or download size | randomised interleaved repetitions, variability reported |
| T5 | **no** additional download and **no** precision-code initialisation in the default lightweight site path | `scripts/report-bundles.mjs` passes with the backend absent; engine-isolation marker check unchanged |

Separate budgets, because a longitude target says nothing about the other
fields the runtime returns:

| # | target | note |
| --- | --- | --- |
| T6 | position vector error ≤ **2 km** for the outer planets, ≤ **0.2 km** for the Moon, against the uncompressed kernel | stated in km, not arcsec, so it is independent of distance |
| T7 | velocity error ≤ **1e-4 km/s** for every body | stations and crossings depend on velocity; a small position error does not bound it |

T2, T6 and T7 are budgets **against the uncompressed prototype**, so they
isolate the representation. T3 is against Swiss, so it includes every other
convention difference and is the weaker statement of the two.

## Verification sets, and the rule for each

Three disjoint sets, deterministically generated by
`tools/make-corpus.mjs` from a fixed seed, committed with their generator.

- **DEV** — tunable. Every candidate may be fitted, inspected and re-fitted
  against it as often as useful.
- **ADVERSARIAL** — built to break things: segment boundaries and the samples
  immediately either side, coverage edges, 0/360 wraparound, conjunctions and
  oppositions, stations and slow-motion intervals, corrupted and truncated
  packs, unsupported options. Read freely while diagnosing a failure; never
  fitted against.
- **HOLDOUT** — opened once, at the end, for the final numbers. If it is opened
  earlier to guide a change, it is spent: it becomes regression data and this
  file is amended to say so.

The previous study's 24-case corpus (`swiss-benchmark/tools/corpus.mjs`) is
**already spent** — it guided the prototype — so it carries forward as
regression data, not as evidence of generalisation.

Dense sampling establishes sampled error over the sampled region. It is not a
mathematical bound, and nothing in this study will call it one. Where a bound
can be derived analytically — Chebyshev truncation, coefficient quantisation,
derivative evaluation — it is derived and labelled as proven, separately from
the empirical end-to-end figure.

## Candidates

Three, per the brief, each with a stated hypothesis before implementation:

- **A — truncate/quantise in place.** Keep the source segmentation; drop
  high-order coefficients and store the rest at reduced precision under an
  explicit error budget. Hypothesis: outer planets tolerate aggressive
  truncation because their Chebyshev spectra decay fast; the Moon does not.
- **B — refit adaptive segments.** Choose degree and segment length per body
  from validation error and boundary behaviour. Hypothesis: beats A at equal
  size because the source segmentation is uniform and the bodies are not.
- **C — residual correction over the lightweight model.** Fit a small
  correction to VSOP87-based output. Hypothesis: cheapest of the three if the
  residual is smooth, and it inherits the lightweight model's failure modes.

A candidate may be replaced by a better-justified method, with the reason
recorded before the replacement is measured.

## Honesty conditions

- No Swiss output is a fitting target anywhere. Swiss is an instrument.
- Compression over equal coverage and cropping coverage are **two different
  experiments** and are reported separately. Cropping is not a compression win.
- The Moon and the difficult bodies stay in every headline. Nothing is dropped
  to improve a number.
- No single weighted score. The trade-offs are reported as a set: smallest
  acceptable pack, fastest acceptable runtime, highest-precision candidate.
- A runtime quality field states whether its bound is mathematical, empirical,
  inherited or unknown. "Certified" is not used.
- Better agreement with a shared ephemeris model is not a claim about physical
  astronomy, and will not be written as one.

## Amendment 1 — 2026-09-20, before any candidate was fitted

The corpus generator was corrected twice while being built, both times because
a check inside it refused its own output. Recorded here because amending a
preregistration after seeing results is exactly what this file exists to
prevent, and the distinction is that nothing had been fitted yet.

1. **Boundary instants collided across sets.** `boundaries()` picked record
   edges at fixed fractions of coverage and varied only the place by seed, so
   dev and adversarial shared instants. The disjointness assertion caught it.
   Each set now takes its own fractions.

2. **Two geometry specs were impossible, and the resolver answered anyway.**
   Mercury and Venus were asked for opposition, which inferior planets never
   reach; the resolver returned a conjunction, because the elongation function
   wraps and its jump from −180 to +180 reads as a sign change. Fixed three
   ways: a continuity guard so a wrap is never mistaken for a root, an
   acceptance predicate so the derivative's minima are not mistaken for its
   maxima, and greatest-elongation specs in place of the impossible ones. A
   verification gate now refuses to write the corpus unless every resolved
   instant shows the geometry its spec asked for.

The corpus as frozen: **244 dev / 182 adversarial / 204 holdout** cases,
**2100 / 1380 / 1700** body-rows in the non-spec cases, 102 geometry instants
all verified, generated byte-identically on repeat runs.
